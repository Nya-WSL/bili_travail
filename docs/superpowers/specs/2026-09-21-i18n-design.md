# bili_travail 多语言（i18n）设计规格

日期：2026-09-21
状态：待实现

## 1. 背景与目标

加班姬目前所有界面文案硬编码为中文。目标：

- 支持**简体中文**与**English**两种界面语言
- **默认根据系统语言自动切换**，无需用户干预
- 用户可在设置页手动选择语言（含「跟随系统」）
- **日志内容保持不变**，一律中文

## 2. 非目标（明确不翻译）

- 所有 `logger.*` 日志输出
- `changelog.json` 中已发布的历史条目正文（95 条，成本高且属发布记录）
- 服务器下发的公告、工单回复等远程内容
- 用户数据：礼物名、礼物玩法配置名、保存的倒计时名称
- 配置文件中的取值（颜色、端口等）
- 礼物表数据（`libs/gift_mapping.py`）

## 3. 目录结构

```
locales/
  zh-CN.json       # 简体中文（默认语言、回退语言）
  en-US.json       # English
libs/i18n.py       # 翻译与语言管理
```

新增语言只需在 `locales/` 放置 `<语言代码>.json`，代码中无需注册。

## 4. 语言文件格式

- 文件名即语言代码：`zh-CN.json`、`en-US.json`
- **扁平 key**，点号分命名空间，便于 grep / diff / 漏翻检查
- 保留 key `__language_name__`：该语言的**母语显示名**，用于下拉展示（新增语言时自包含）
- 占位符使用 `{}` + `str.format(**kwargs)`

```json
{
  "__language_name__": "简体中文",
  "main.tab.account": "账号设置",
  "main.btn.start": "开始",
  "blind_box.profit": "盈亏：{profit}电池"
}
```

## 5. libs/i18n.py API

| 函数 | 说明 |
|---|---|
| `available_languages() -> dict[str, str]` | 扫描 `locales/*.json`，返回 `{语言代码: 母语名}`；读取失败用文件名兜底；目录为空时返回默认语言 |
| `detect_system_language() -> str` | 检测系统语言并映射为受支持的语言代码，失败返回默认语言 |
| `resolve_language(config_value: str) -> str` | `auto`/空 → `detect_system_language()`；否则返回配置值 |
| `set_language(lang: str) -> None` | 设置当前语言并加载对应 JSON（带缓存） |
| `get_language() -> str` | 当前语言代码 |
| `t(key, **kwargs) -> str` | 翻译；当前语言缺失 → 回退 `zh-CN` → 仍缺失返回 key 本身 |

约定：

- 常量：`DEFAULT_LANG = "zh-CN"`、`SUPPORTED_FALLBACK_ORDER = ["zh-CN"]`
- 语言文件在启动时加载一次并常驻内存
- `available_languages()` 每次调用都重新扫描目录（文件数量极少，开销可忽略），以支持运行中新增语言文件后立即出现在下拉里
- 排序：默认语言 `zh-CN` 优先，其次 `en-US`，其余按语言代码升序

## 6. 系统语言检测

- Windows：`ctypes.windll.kernel32.GetUserDefaultUILanguage()`，取 LANGID 主语言位判断语种
- 其他平台：`locale.getdefaultlocale()`，其次环境变量 `LANG`
- 映射：`zh*`（含 `zh-TW`/`zh-HK`，首版统一归 `zh-CN`）→ `zh-CN`；`en*` → `en-US`；其余 → `zh-CN`
- 检测抛异常 → `zh-CN`

## 7. 配置与设置页

- `config.toml` 新增 `[general] language`，默认 `"auto"`；取值 `auto` / `zh-CN` / `en-US` 及后续任意语言代码
- `libs/config.py` 的示例配置同步逻辑需补充该键，确保升级时自动补齐
- 「程序设置」tab 增加「语言」下拉：
  - 选项 = `{"auto": t("settings.language_auto")}` + `available_languages()`
  - `auto` 显示为「跟随系统 / Follow system」（随当前语言变化）
  - 选中后写回 `config.toml` 并 `ui.notify(t("settings.language_restart"))` 提示**重启后生效**
  - 切到「程序设置」tab 时重新扫描并 `set_options`，实现下拉自动刷新
- `ui.run(language=...)` 同步设置 Quasar 内置组件语言（`zh-CN` / `en-US`）

**不采用**页面热重载：避免运行中的倒计时与弹幕连接状态丢失。

## 8. 文案 key 规范

命名空间：`main.*`（主界面）、`settings.*`、`notify.*`、`dialog.*`、`about.*`、`capture.*`（OBS 叠加层）、`count.*`（统计页）、`sim.*`（模拟测试器）、`common.*`（确认/取消/关闭等）、`format.*`（时间单位）

## 9. 改造清单

第一批（主界面与设置）：

- `main.py`：tab 标题字典、按钮文案、约 47 处 `ui.notify`、tooltip、礼物设置弹窗玩法标签（加时/减时/加倍/减半/清空/随机）、盲盒盈亏弹窗、模拟测试器

第二批（子页面与库）：

- `pages/about.py`、`pages/capture_cd.py`、`pages/count.py`
- `libs/format.py`：`format_seconds` 的单位（"1小时2分钟" ↔ "1h 2m"）
- `libs/update.py`、`libs/check_runtime.py` 中的用户可见提示
- `libs/changelog.py`：仅翻译标题与空态文案

## 10. 打包

`build.py` 增加：

```python
shutil.copytree("locales", Path("dist", "start", "locales"), dirs_exist_ok=True)
```

与 `static/`、`data/` 同样随程序目录分发，运行时按相对路径 `locales/` 读取（与现有资源约定一致）。

## 11. 错误处理

- `locales/` 目录缺失或为空 → 回退默认语言，日志告警一次
- 单个语言文件损坏（JSON 解析失败）→ 跳过该文件、日志告警，其余语言仍可用
- key 缺失 → 回退 `zh-CN` → 仍缺失返回 key 原文（便于发现漏翻）并打 debug 日志
- 检测到未知语言代码 → 回退 `zh-CN`

## 12. 验证方式

- `language = "en-US"` 启动：主界面、设置、各弹窗、OBS 页面文案均为英文，无中文残留
- `language = "auto"`：分别在中文系统与英文系统下启动，验证自动切换
- 删除 `locales/en-US.json` 后启动：下拉仅剩中文与「跟随系统」，程序不报错
- 运行中向 `locales/` 新增 `ja-JP.json`：切到设置 tab，下拉立即出现该语言
- 日志检查：`logs/` 中日志仍为中文
- 打包后运行 `dist/start/start.exe`，确认 `locales/` 已随包分发且语言切换正常

## 13. 风险与对策

- `main.py` 约 2200 行、150 余处文案，一次性替换易漏 → 按第 9 节分两批，每批完成后人工走查
- 品牌词：程序名保留 `bili_travail`，界面标题译作 `Bili Travail`
- 英文文案为直译，术语（如「盲盒」→ Blind Box、「电池」→ Battery、「加时/减时」→ Add/Reduce time）需人工确认
- 打包后 `locales/` 依赖工作目录，与现有 `data/`、`static/` 同一约定；通过直播姬唤起时 `main.py` 已切换工作目录，行为一致
